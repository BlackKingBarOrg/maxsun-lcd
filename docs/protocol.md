# MAXSUN 主板小屏 USB 协议

适用：MAXSUN MS-iCraft Z890 Pacific 板载 3.4 英寸屏（官方软件说明里写 Vertex、Pacific、Arc 共用）。
来源：静态分析官方 MAXSUN VIEW V2.1.0.5 和它自带的屏幕固件，2026-10-20 在真机上验证。

## 设备

- USB `0416:5021`，厂商字符串 `Maxsun`，产品 `USB_HID`，USB 2.0 高速，挂在主板内部针脚上。
- 主控：新唐 **N9H26**（ARM926EJ-S，带 H.264 硬解）。
- 屏幕：竖屏 **412×960**，图片上方就是屏幕上方，不需要旋转，也没有镜像。
- 两个 HID 接口，都没有 report ID（写入时在最前面补一个 `0x00`）：

| 接口 | 用途 | 报文长度 | 本机节点 |
|---|---|---|---|
| 0 | 命令 / 回包 | 64 字节 | `/dev/hidraw2` |
| 1 | 数据（JPG 等） | 1024 字节 | `/dev/hidraw3` |

节点编号可能变化，代码通过 sysfs 按 VID:PID 和 interface number 查找。

## 命令包

64 字节，固定格式 `[cmd] 01 00 80 [参数…]`，后面补 0。设备在接口 0 上回包，同样以 `?? 01 00 80` 开头。

| cmd | 官方软件里的用途 | 参数 | 设备回包 | 风险 |
|---|---|---|---|---|
| 0x01 | 握手 / 状态查询；连上时发一次，之后每 3 秒发一次 | 无 | 状态包，见下文 | 安全 |
| 0x0E | 推一帧实时 JPG | 见"图像头" | 无 | 安全 |
| 0x0F | ClearPNG：清除叠加层；同步主题前也会先发 | 无 | 原样回传 | 安全，**能去掉 Loading...** |
| 0x07 | 屏幕开关：打开 | `[4]=01` | 原样回传 | 安全 |
| 0x08 | 屏幕开关：关闭 | `[4]=01` | 原样回传 | 安全 |
| 0x0C | 背光 | `[4]=1..10`，PWM 占空比 = 值²%，只存在 RAM 里 | 原样回传 | 安全（已在真机验证） |
| 0x10 | 休眠时继续播放 | `[4]=值` | 原样回传 | 未测试 |
| 0x11 | 电源检测 | `[4]=值` | 原样回传 | 未测试 |
| 0x03 | 同步 JPG 到屏幕存储 | `[4]=参数` + 图像头 | 原样回传 | **写闪存，别碰** |
| 0x04 | 同步原始 BGRA 图到屏幕存储 | 图像头 | 原样回传 | **写闪存，别碰** |
| 0x0A | 恢复设备 | `[4]=01` | — | **别碰** |
| 0x02 | 固件 / 文件传输（固件升级按钮调用） | 类型 + … | 原样回传 | **绝对别碰** |
| 0x09, 0x0D | 固件里有处理，官方软件没用到 | ? | ? | 未知 |

### 握手回包（0x01）

本机实测：

```
01 01 00 80 01 10 01 01 00 00 00 01 00 00 00 00 00 00 0a 01 07 00 00 00 00 00 01 01 01 00 …
```

- 官方软件判断连接成功的条件：`[9] == 0`、`[10] == 0`、`[0x13] == 1`。
- `[18]`：背光档位（1–10，出厂 10）。0x0C 的处理函数只写状态结构体偏移 0x13 并设置 PWM（`0x30220`），不写闪存，断电后恢复默认。
- `[20]`：显示模式。`0x0a` = 待机（播放 `ideal.h264`），`0x07` = 实时模式。
- 第一次握手时 `[14..17]` 不为 0（`f0 b4 93 09`），之后变成 0，含义未知。

## 图像头（0x0E / 0x04）

```
[0]    cmd
[1..3] 01 00 80
[4..7]   包数 = ceil(长度 / 1024)   LE32
[8..11]  校验 = 所有字节相加       LE32（取 uint32）
[12..15] 长度                     LE32
```

0x02 / 0x03 在 `[4]` 多一个参数字节，后面三个字段依次后移到 5..16。

## 推一帧实时画面

1. 渲染 412×960 的图（官方用 `QImage::scaled`，不保持宽高比、快速变换），编码成 JPG（官方用 Qt 默认质量）。
2. 在接口 0 发 `0x0E` + 图像头。
3. 等 1 ms。
4. 把 JPG 按 1024 字节切块写到接口 1，最后一块补 0。中间不等 ACK，设备也不回包。

官方软件每 10 ms 触发一次定时器，每 30 ms 推一帧；实测每秒 20–33 帧都很稳定。停止推送后，最后一帧会一直留在屏幕上。

## 启动顺序和 Loading... 叠加层

正确的顺序是 **0x01 → 0x0F → 0x0E…**。

固件进入待机模式（模式 0x0a，播放 `C:\h264\ideal.h264`）时，会在 OSD 叠加层的 (x=160, y=920) 处画一行 `Loading...`。推实时帧会把模式切到 7，但这行字还留着；持续推帧、每 3 秒心跳、发 0x07 都清不掉，**只有 0x0F 能清**。

## 主题视频格式（存进屏幕用，目前没用到）

416×960 的 H.264（宽度对齐到 16）。官方转码命令：

```
ffmpeg -i in.mp4 -c:v libx264 -profile:v baseline -level 1.0 -crf 18 -tune film -r 24 -an -f h264 out.h264
```

另配一个 `.htxt`，每行一个数，是逐帧的字节长度。

## 固件笔记（V18，供以后继续逆向）

- 固件文件：`GPIO_CONFIG_FLOATINGPWM100AUXNORECODE20250923_V18.bin`。前 16 字节是文件头，后面的镜像加载到地址 0，ARM 模式。
- 命令分发函数：`0x28b04`，命令缓冲区在 `0x500d80`，状态结构体在 `0x500834`。
- 主循环里选择显示模式的代码：`0x33128`。画 `Loading...` 的位置：`0x334a0`。
- 屏幕存储（FAT）里的文件：`C:\h264\{poweron,Poweroff,ideal}.{h264,txt}`、`C:\pic\{poweron,Poweroff,ideal}.jpg`、`C:\sys\sysinfo.txt`。
- 底部状态栏能显示 BIOS 开机阶段：`CPU INIT`、`Memory INIT`、`Display INIT`、`USB INIT`、`Ready to Boot`、`BIOS setup`、`FLASH BIOS`，以及对应的错误信息（编号 0–13，字符串表在 `0x34b98`）。

## 官方软件笔记

- `MAXSUN_View.exe` 是 Qt5 C++ 原生程序，通过 `hidapi.dll` 访问设备。moc 元数据把方法名都保留了，类名是 `MainWidget`，`qt_static_metacall` 在 `0x48a3e0`。
- 命令包组装函数在 `0x47a0d0`–`0x47f190`；`hid_write` 的封装是 `0x479310`（通道 0 = 命令接口，通道 1 = 数据接口）。
- 回包校验在 `0x4449e0`：0x02、0x03、0x04、0x07、0x08、0x0C、0x0D、0x10、0x11 这些命令要求设备原样回传。
